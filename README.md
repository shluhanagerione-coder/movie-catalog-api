# Мой проект: Каталог фильмов (Movie Catalog API)

## Краткое описание проекта
Я разработал RESTful API для управления каталогом фильмов и оформления заказов. Приложение позволяет пользователям просматривать список доступных фильмов, искать их по различным критериям (жанр, рейтинг), сортировать по цене, а также создавать новые заказы на покупку или аренду. 

---

## Основные возможности приложения
*   **Управление каталогом фильмов:** получение списка всех фильмов и детальной информации о конкретном фильме по его ID.
*   **Поиск и навигация:** гибкая фильтрация фильмов по жанру и минимальному рейтингу, а также сортировка списка по цене.
*   **Система заказов:** создание заказов на фильмы с автоматической фиксацией количества и статуса.
*   **Интерактивная документация:** автоматическая генерация Swagger UI эндпоинтов для тестирования API в реальном времени.

---

## Технологический стек
*   **Язык программирования:** Python 3.12
*   **Фреймворк:** FastAPI (асинхронный веб-фреймворк)
*   **База данных:** SQLite (работает через асинхронный драйвер aiosqlite)
*   **ORM:** SQLAlchemy 2.0 (декларативные модели и асинхронные сессии)
*   **Миграции базы данных:** Alembic
*   **Валидация данных:** Pydantic v2
*   **Сервер приложений:** Uvicorn

## Быстрый старт

Для запуска моего проекта локально выполните следующие шаги:

### 1. Клонирование репозитория
```bash
git clone <ССЫЛКА_НА_ВАШ_РЕПОЗИТОРИЙ>
cd product_catalog
```

### 2. Настройка виртуального окружения и установка зависимостей
```bash
python -m venv venv
source venv/Scripts/activate  # Для Windows (Git Bash)
# или source venv/bin/activate для Linux/macOS

pip install -r requrements.txt
```

### 3. Применение миграций базы данных
Я использую Alembic для управления базой данных, поэтому перед запуском необходимо применить миграции структуры:
```bash
alembic upgrade head
```

### 4. Запуск приложения
Запустите сервер разработки с помощью Uvicorn:
```bash
uvicorn src.main:app --reload
```
Интерактивная документация API (Swagger UI) будет доступна по адресу: [http://127.0.0](http://127.0.0)

## Основные эндпоинты

### Фильмы (`/products`)
*   `GET /products` — Получить список всех фильмов (поддерживает фильтрацию и сортировку).
*   `GET /products/{product_id}` — Получить подробную информацию о конкретном фильме по его ID.

### Заказы (`/orders`)
*   `POST /orders` — Создать новый заказ на фильм.

---

## Фильтрация и сортировка

При совершении запроса `GET /products` доступны следующие Query-параметры:

*   `genre` (строка, необязательный) — Фильтрация фильмов по конкретному жанру.
*   `min_rating` (число с плавающей точкой, необязательный) — Вывод фильмов с рейтингом не ниже указанного.
*   `sort_by_price` (строка, необязательный) — Сортировка списка фильмов по цене. Принимает значения `asc` (по возрастанию) или `desc` (по убыванию).

## Модель данных

В базе данных я реализовал две связанные сущности:

1.  **Product (Фильм / Продукт):**
    *   `id` (Integer, Primary Key) — Уникальный идентификатор.
    *   `name` (String) — Название фильма.
    *   `description` (String) — Описание сюжета.
    *   `price` (Float) — Стоимость покупки/аренды.
    *   `rating` (Float) — Рейтинг фильма.
    *   `genre` (String) — Жанр.

2.  **Order (Заказ):**
    *   `id` (Integer, Primary Key) — Уникальный идентификатор заказа.
    *   `product_id` (Integer, Foreign Key) — Идентификатор приобретаемого фильма.
    *   `quantity` (Integer) — Количество.
    *   `status` (String) — Статус выполнения заказа (по умолчанию `pending`).

---

## Ограничения базы данных
*   Поля `id` у сущностей `Product` и `Order` являются первичными ключами (**Primary Key**) и генерируются автоматически, гарантируя уникальность записей.
*   Поле `product_id` в таблице заказов является внешним ключом (**Foreign Key**), ссылающимся на существующий `id` в таблице продуктов. Это предотвращает создание заказов на несуществующие фильмы.
*   Поля названий (`name`), цен (`price`) и связей (`product_id`) имеют ограничение `nullable=False`, запрещающее хранение пустых значений в критически важных свойствах.
